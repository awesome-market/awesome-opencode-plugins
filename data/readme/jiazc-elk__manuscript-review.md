# 正文审核器（Manuscript Review）

> 给一幕/一个序列的正文和可选的前情/幕纲/人物卡/文风参考，让五个写作角色真的吵几轮，最后只交一份“好不好看、哪里不好看、怎么写更好”的报告。
>
> **只读。不改稿。不碰你的文件。**
>
> 当前版本：`0.3.0`（beta）｜OpenCode / Claude Code / Codex 三端适配

## 这是什么

正文审核器是一个面向**已有正文**的写作技巧审核 skill。它不写小说，不做设定，不生成大纲，**也不做设定/逻辑/时间线一致性审查**。它只做一件事：

> **评价这一幕/这个序列/这一章写得好不好看，哪里不好看，有没有更好的写法。**

它默认按**一幕/一个序列**审，而不是一章；因为单章看不出幕逆转、人物弧、求索、伏笔回收、跨章节奏。

## 为什么不是“一个模型写一篇读后感”

单模型审稿有三个常见毛病：

1. **什么都夸/什么都骂**：没有稳定标准；
2. **只挑逻辑错**：设定、时间线、知识边界说一堆，却不告诉你“好不好看”；
3. **越改越像评审团**：把作者的个人风格当成错误铲平。

这个项目用五个写作角色分工 + 多轮对抗 + 证据锚点 + “更好的写法”来解决：

- 场景、对白、描写、节奏各管一段，不越权；
- 人物角色看欲望/矛盾/声音/情感，不做人物卡一致性审判；
- 结构角色看幕功能/逆转/升级/章功能分布；
- 节拍拆解只画地图，不评好坏；
- 魔鬼红队问“这是真好看，还是‘有元素’？”；
- 主持负责最终裁定与报告。

## 五个核心角色（+ 可选秘书）

| 角色 | Stable ID | 管什么 | 不管什么 |
|---|---|---|---|
| 场景、对白与描写 | `scene_dialogue` | 场景目标/转折、beat、对白行动、潜台词、人物声音、描写/POV、节奏、文字 | 幕结构、人物弧最终裁决 |
| 人物与情感 | `character` | 欲望、矛盾、压力选择、魅力、关系、情感落点、人物弧 | 设定/知识边界一致性 |
| 幕/序列结构与节奏 | `story_plot_structure` | 幕功能、激励、渐进复杂化、中点、危机/高潮、收束、章功能分布、节奏 | 人物心理、对白原文 |
| 节拍拆解 | `story_deconstructor` | 单位地图、章节功能、场景/beat、POV/情绪曲线、承诺/回收 | 评好坏、事实/逻辑核证 |
| 写作质量红队 | `devil_critical_review` | 钢人化、误报、虚高、建议副作用、共识偏差、单位是否足够 | 接管专业裁决 |
| 报告整合（可选） | `secretary` | 报告结构、算术、分歧保留 | 新增判断、改裁定 |

主持（Chairman）由主线程担任，不单设子代理。**不派世界观/设定席。**

## 快速开始

### OpenCode

打开本仓库根目录，然后：

```text
用正文审核器审第一卷第一幕（第1–8章）。
正文：/path/to/ch01-08/
前情：/path/to/前情摘要.md
幕纲：/path/to/第一幕幕纲.md
人物卡：/path/to/人物卡.md
目标：好不好看、哪里不好看、怎么改更好。
```

也可以显式点名 skill：`manuscript-review`，或使用 `/manuscript-review` 命令。

### Codex

### 安装到已有小说项目

1. 复制 `.agents/skills/manuscript-review/` 到目标项目的同一路径；
2. 复制你所用宿主的适配层：
   - OpenCode：`.opencode/agents/*.md` + `.opencode/commands/*.md`
   - Claude Code：`.claude/agents/*.md` + `.claude/skills/manuscript-review/`
   - Codex：`.codex/agents/*.toml`
3. 重开项目/会话，让宿主重新发现 skill 与子代理；

## 审核单位：默认不是“一章”

| 单位 | 范围 | 能判 | 不能判 |
|---|---|---|---|
| **单章 `chapter_local`** | 1 章 | 局部场景/对白/描写/节奏/本章功能 | 幕逆转、人物弧、求索、伏笔回收、跨章节奏 |
| **序列 `sequence`**（推荐最低） | 3–8 章 | 序列目标/转折、章功能分布、局部弧、承诺/回收、序列节奏 | 全幕/全书弧、最终高潮 |
| **幕 `act`**（推荐） | 约 8–30 章 | 幕功能、激励、渐进复杂化、中点、危机、高潮、收束、人物弧 | 全书/多卷 |
| **卷/多幕** | 多幕 | 跨幕结构、卷级弧、长线 | 全书终局（除非给全稿） |
| **序章/引子** | 1 章或短序列 | 建立缺失/悲剧/世界规则/悬念、交棒 | 主角弧、整幕逆转 |

只给一章时，审核器会先问“是否只做局部诊断”；不会把单章硬说成整幕。

## 三种深度

| 模式 | 什么时候用 | 发生什么 |
|---|---|---|
| `quick` | 短序列、只想快速看 | 独立审 + 轻量收敛，3–5 条关键问题 |
| `standard`（默认） | 大多数幕/序列 | 独立审 → 交叉质询 → 收敛；两轮讨论 |
| `deep` | 卷末、高潮、关键转折、争议大的稿 | 再加一轮复核与魔鬼终检；逐章分析 |

深度 ≠ 审核单位：`quick/standard/deep` 决定讨论轮次；`chapter/sequence/act` 决定评审范围。

## 报告里有什么

1. **审核摘要**：审核单位/章节类型、总分、写作技巧分、好不好看、最该先改的三处、发布建议。
2. **审核范围与依据**：素材状态、上下文覆盖、能判什么/不能判什么。
3. **单位地图**：章功能表、场景/beat、POV/情绪曲线、承诺/回收。
4. **六维写作评价**：场景与戏剧、对白与人物声音、描写与文字、节奏与可读性、人物与情感、幕/序列效果。
5. **写作技巧评分**：10 项 1–5 分 + Craft Index。
6. **P0/P1/P2 清单**：每条带位置、证据、读者影响、改法。
7. **更好的写法**：2–4 组“原文 → 可尝试 → 技法”，短句示例，不是代写。
8. **章节分布**：逐章功能/强度/主要问题/局部分（只作诊断）。
9. **圆桌争议**：谁和谁没谈拢、主持怎么裁、还缺什么。
10. **亮点与保留项**：哪些地方不要改坏。
11. **评分明细 + 覆盖范围 + 只读声明**。

示例结构见 `.agents/skills/manuscript-review/templates/REPORT_TEMPLATE.md`。

## 评分怎么算

**六个写作维度**，默认权重：

```text
场景与戏剧效果 25% + 对白与人物声音 20% + 描写与文字 20%
+ 节奏与可读性 15% + 人物与情感 10% + 幕/序列效果 10%
```

- 1–10 分，0.5 刻度；
- P0 是**写作技巧阻断**（场景无功能、叙述不可读、主角完全无欲望、幕级逆转缺失等），触发总分上限（1 条 ≤ 6.5，2 条 ≤ 5.8，3 条以上 ≤ 5.0），**只压不抬**；
- 置信度低时给区间分，不装作精确；
- 分数必须能由 findings 支撑，不能先定分再找理由。

**写作技巧分（Craft Index）** 回答“好不好看”，与总分并列：

```text
场景目标/转折 / 对白行动/潜台词 / 人物声音 / 描写/感官/POV / 节奏/句法
/ 情绪落点 / 人物欲望/矛盾 / 人物弧/关系 / 幕·序列升级/逆转 / 类型契约/读者体验
→ 10 项各 1–5 分 → 平均 × 2 = 写作技巧分（1–10）
```

- 它不加权进总分，避免重复计分；
- 写作技巧分明显低于总分 → 整体尚可，但文字/场景执行是短板；
- 写作技巧分明显高于总分 → 文字/场景有亮点，但幕结构/人物/类型契约拖后腿。

详细规则：`.agents/skills/manuscript-review/runtime/SCORING_RUBRIC.md`；技巧清单：`WRITING_CRAFT_LENS.md`。

## 不评什么

**本 skill 不评设定/逻辑/时间线/知识边界一致性。** 这类分析容易分散注意力，也不是本项目的强项。

- 素材（前情/幕纲/人物卡/文风）用于理解人物、氛围、前情和类型契约，**不用于一致性审判**；
- 用户要求“查设定/逻辑/时间线”时，说明超出本 skill 范围，建议另用工具或人工核对；
- 报告不出现“设定冲突 P0”“知识泄漏”“时间线错误”这类主评。

## 只读保证

- 不修改、不重命名、不移动、不删除、不创建用户文件；
- 不执行写入型命令、不跑脚本、不做 git 写操作；
- 报告默认只输出在对话里，不在磁盘上生成；
- 用户明确要求“保存报告”时，只在指定路径新建一个报告文件，不覆盖已有文件；
- 用户要求“直接帮我改”时，拒绝写入，改为给修改方案。

准确表述是：**本次运行未调用任何写入操作**。详见 `.agents/skills/manuscript-review/runtime/READ_ONLY_AND_SAFETY.md`。

## 素材用途

| 素材 | 用来做什么 | 不要用来做什么 |
|---|---|---|
| 前情/上一幕结尾 | 理解人物状态、未回收承诺、读者已知信息 | 不做时间线审判 |
| 幕纲/大纲 | 理解本幕功能、转折点、作者意图 | 不当“必须逐条兑现”的硬合同 |
| 人物卡 | 理解人物声音、关系、欲望、底线 | 不做知识边界/能力数值审判 |
| 文风样本 | 理解作者声音、类型语感、句子节奏 | 不要求作者复制样本 |
| 平台/读者要求 | 调整类型契约、节奏、尺度 | 不当法律/平台裁决 |
| 读者反馈 | 关注点参考 | 不当质量结论 |

**素材的沉默不是禁止。** 人物卡没写“他不会飞”，不等于他飞了就是写错；本 skill 不评这个。

## 自定义

- **改角色关注点**：编辑 `.agents/skills/manuscript-review/roles/<id>.md`。
- **改写作技巧清单**：编辑 `runtime/WRITING_CRAFT_LENS.md`。
- **改评分/权重/上限**：编辑 `runtime/SCORING_RUBRIC.md`，但要在报告里披露调整。
- **加类型契约**（网文/悬疑/言情等）：在 `runtime/REVIEW_CHECKLISTS.md` §7 扩展。
- **加宿主**：在对应目录加薄适配器，指向同一个 `roles/<id>.md`，不要复制出第二套逻辑。

## 开发自检

```bash
python3 -m unittest discover -s tests -v
python3 .agents/skills/manuscript-review/scripts/check_report.py examples/sample_report.md
```

`check_report.py` 用于检查一份**已经保存**的报告是否包含必需章节、只读声明、评分范围、P0 证据锚点、写作技巧评分与未替换占位符。它是离线工具，不属于审核运行时。

## 已知边界

- 它评的是**这一单位当前的样子**，不是作者的潜力、市场表现或文学史地位。
- 单章只能做局部诊断，不能判断幕逆转、人物弧、求索、伏笔回收。
- 它不评设定/逻辑/时间线一致性；需要这类检查请另用工具或人工。
- 评分是诊断工具，不是终审判决；不同评审标准下分数会变。
- 它不会为了显得专业而硬凑问题；问题少时报告会短。
- 它不代写。示例最多 1–2 句，且明确标注“不是代写”。

## 设计来源

角色分工、证据优先、只读边界、越权纪律、钢人化后再攻击、秘书不新增判断等治理思路，来自早期的 **Novel Council** 项目。本项目把这些角色重组为**面向已有正文的写作技巧审核流程**，不再承担 Canon、规划、设定生成或逻辑一致性审查职责。
