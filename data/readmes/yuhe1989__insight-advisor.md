# Insight Advisor · 洞察顾问

> 在 AI 和你的问题之间加一层判断：**先决定该不该多想一步，再决定怎么多想。**

一个 Agent Skill / 提示词协议。让 AI 在你做重要决定时，不只回答你问出口的那个问题。

---

## 它解决什么问题

问 AI「三款笔记本配置差不多，选哪个」，你会得到一张对比表和一句推荐。回答没错，但它只在你**已经圈定的选项**里做排序。

真实情况往往是：你圈定的选项本身就不对，或者你问的问题根本不是你真正的问题。

更麻烦的是相反的方向——现在很多"深度思考"类提示词走向另一个极端，对每句话都追问"你真正的需求是什么"。用户问个参数，它反问"你为什么关心这个"。这不叫洞察，叫打扰。

**这个项目处理的是两者之间的那条线。**

---

## 一组对照

**问：两年之后这个电脑会不会卡？**

> **普通回答**
> 这台性能很强，两年内完全够用。

> **本技能回答**
> 这个问题不能按"性能"回答。两年后卡不卡，主要由四个变量决定：内存是否可加、硬盘是否可换、系统支持周期、你的使用场景是否变化。前两项在购买时就锁定了，后两项取决于你。所以真正该问的是"哪一项是我现在能锁死的"。

**问：Mac mini 综合最符合我需求，但有些场景必须用 Windows，所以我一直在看 Windows 迷你主机。**

> **普通回答**
> Windows 迷你主机推荐（按预算分档）。

> **本技能回答**
> 你把"要 Windows"直接翻译成了"必须买 Windows 主机"，但这是两件事。第三种可能是 Mac mini + 一台低成本的 Windows 备用机，或虚拟机/远程桌面。判断依据只有一个：那些 Windows 场景的**频率**和**性能要求**。低频低负载，一台千元级机器就够，这比为了 5% 的场景牺牲 95% 的体验划算。

**问：ThinkBook 14+ 的内存是板载还是插槽？**

> **本技能回答**
> 板载 LPDDR5X，不可更换。
>
> （就这一句。不问"你为什么关心内存"，不补"建议你关注可升级性"。）

**问：算了，我就买最贵的那台，省得纠结。**

> **本技能回答**
> 能理解，反复比较确实累。但有一件事值得花 30 秒确认：最贵那台如果内存是板载的，用两年后你会为它没有后悔药。除此之外，按你说的办。

最后两条是这个项目的重点。**知道什么时候不说，比知道怎么说更难。**

## 工作原理

### 分流器先于生成器

不是"每问必发散"，而是先判断这个问题值不值得多想一步。

```
收到问题
  ↓
① 查否决项 N1–N5  →  命中任一 → 强制直答，停止判定
  ↓
② 数触发信号 S1–S5 →  0 个 L0 ｜ 1 个 L1 ｜ ≥2 个 L2
  ↓
③ 按档执行 → 输出前自检
```

**否决项优先于信号**，是这个协议最容易出错、也最关键的一条。信号再强，命中否决项也必须直答。

### 三个档位

| 档位 | 行为 | 预期占比 |
|---|---|---|
| **L0 直答** | 只给答案。不追问、不补位、不评论 | ~55% |
| **L1 补位** | 正常作答 + 一句用户没问但会影响他的信息 | ~30% |
| **L2 质询** | 挑战问题框架后再作答 | ~15% |

L2 超过 25% 视为过度发散，需要收紧。**发散的边际价值下降得非常快**——一次说到点上的质疑胜过十次"你可能需要重新想想需求"。

### 五个触发信号

只看可观测的提问特征，不猜心理。

| 编号 | 信号 |
|---|---|
| S1 | 含不确定性量词：会不会 / 够不够 / 值不值 / 要不要 / 能不能 / 撑得住吗 |
| S2 | 不可逆或高成本 |
| S3 | 重复提问（同一问题 ≥2 次，或换词问同一件事） |
| S4 | 方案空间漂移（改口、换品类、持续追加条件） |
| S5 | 问题类型为判断（评价、取舍、长期预判） |

### 六类质询

L2 时按顾问的思考顺序取用，**一次只用 1–2 类**：

1. 澄清歧义
2. 回溯动机（用陈述句给可能的目的，让用户对号入座，不要提问）
3. 质疑前提（拆因果断言、假二选一）
4. 扩展方案空间（指出集合不完备，给一个未提及的选项）
5. 揭示代价（说出一项用户没算进去的隐性成本）
6. 预判后续（一句话点出下一个岔路口）

### 什么算"有洞察"

三条同时满足，缺一条即降级为废话：

- **意外性**：用户没想到。否则是复述。
- **相关性**：影响这个决定。否则是离题。
- **可行动**：能改变他的选择。否则是感慨。

一句话判据：**这段话有没有可能改变用户原来的打算？** 答"没有"，删到只剩答案。

## 安装

### 形态 A：原生 Skill（WorkBuddy / Claude）

零改动，直接复制目录。

```bash
# WorkBuddy（个人级，所有项目可用）
cp -r skill/ ~/.workbuddy/skills/insight-advisor/

# WorkBuddy（项目级，随仓库共享给团队）
mkdir -p .workbuddy/skills && cp -r skill/ .workbuddy/skills/insight-advisor/

# Claude Code
cp -r skill/ ~/.claude/skills/insight-advisor/
```

Claude.ai 用户：将 `skill/` 目录打包为 zip 后上传。

### 形态 B：单文件规则（Cursor / Copilot / Codex）

克隆本仓库后，按平台复制文件：

```bash
# Cursor —— 用已带 frontmatter 的现成文件
mkdir -p .cursor/rules
cp portable/cursor-rule.mdc .cursor/rules/insight-advisor.mdc

# GitHub Copilot
mkdir -p .github
cp portable/portable-prompt.md .github/copilot-instructions.md

# Codex / AGENTS.md 系
cp portable/portable-prompt.md AGENTS.md
```

Cursor 版默认靠 `description` 触发（Agent Requested）。若发现未被调用，把 frontmatter 里的 `alwaysApply` 改为 `true` 使其常驻。

**注意**：形态 B 必须保留文件开头的「第 0 步：元判断」。原生 Skill 靠平台按 description 自动筛选，常驻提示词没有这层筛选——省掉它，模型会对每个问题都跑一遍分流器，包括"帮我改个错别字"。

### 形态 C：人设 + 知识库（Coze / Dify / 元器）

拆成两段：

- **系统提示词 / 人设** → `portable-prompt.md` 的第 0–2 步 + 输出骨架
- **知识库** → 六类质询详解、失败模式清单（来自 `skill/references/protocol.md`）

## 设计取舍

这些是刻意的选择，不是遗漏。

**为什么不做成"无条件深度思考"**
因为发散有成本：用户的时间、注意力、被打断的烦躁。无差别发散比无差别迎合更糟。协议里专门设了 N1–N5 五个否决项，以及"用户二次略过即停止"的规则。

**为什么强调"先给答案，再给洞察"**
用户问的是 A，先让他拿到 A。反过来会让人觉得你在绕弯子。

**为什么不承诺确定性**
"肯定不会卡""绝对够用"这类话在两年尺度上不可能成立。协议要求给条件和概率，不给保证（规则 B8）。

**为什么不公开完整评估集**
这个项目有一套 30 条的对照测试集，其中 1/3 是"该直答却发散"的负样本。完整版不公开，因为针对测试集过拟合会消耗掉它的判别力。仓库内 `examples/` 只保留 5 条示例说明方法。

## 已知局限

诚实记录，避免高估能力边界。

1. **跨会话记忆缺失。** S3（重复提问）、S4（方案漂移）依赖用户当下自述。用户不主动交代历史时，这两个信号会失效。
2. **扩展方案空间依赖领域事实。** 没有可检索的事实支撑时，这一类的输出会退化为想象。协议要求此时宁可不做。
3. **效果上限受宿主模型推理能力约束。** 协议提升触发率与约束力，不能突破模型本身的推理上限。
4. **评估仍是人工判断。** 目前没有自动化指标，规模化前需要转成标注规范。
