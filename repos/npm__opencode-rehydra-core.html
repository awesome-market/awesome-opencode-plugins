README

为 AI 工作流、编程助手和浏览器场景提供 PII 安全防护。
  检测、替换、加密，并在需要时还原真实值。



  English



  



  pi install npm:pi-rehydra


 问题所在

当你把代码、消息或文档发给 LLM 时，真实姓名、邮箱和 API Key 会一并离开你的机器。已有的匿名化工具要么永久删除 PII（那样对话就断了），要么只是临时遮盖（那样模型无法推理）。

你需要的是化名：模型能拿来推理，你的工具又能还原回去。

 Rehydra 的做法

1. 检测 — 正则捕获结构化 PII（邮箱、电话、英国邮编、IBAN、信用卡卡号）。本地 NER 模型（ONNX，不联网）捕获非结构化 PII（人名、机构、地点）。
2. 替换 — 每个 PII 值获得一个稳定占位符：。模型用占位符而不是真实数据来工作。
3. 持久化 — 同一实体在整个会话的每条消息里都是同一个 ID。模型能维持关系一致性，却从未看到真实 PII。
4. 还原 — 当响应需要变回真实值时（写文件、执行 bash 命令、给出最终答案），Rehydra 从加密映射中还原原始值。

 快速开始

 Pi 扩展

bash
pi install npm:pi-rehydra


在 ~/.pi/agent/settings.json 中添加包声明与配置：

json
{
  "packages": [
    { "source": "npm:pi-rehydra" }
  ],
  "rehydra": {
    "envFiles": [".env", ".env.local"],
    "redactValues": ["sk-live-abc123..."]
  }
}


它拦截 Pi 与 LLM 之间的对话：.env 文件中的密钥在离开本机前被替换为占位符，在工具执行前被还原。发送给模型的消息与工具结果走脱敏（context_with_system / tool_result），工具入参与最终回答走还原（tool_call / message_end）。配置项、工作钩子与限制详见 Pi 扩展文档。

 为什么选 Rehydra

 可逆，而非破坏性

多数 PII 库做的是永久遮盖或删除。Rehydra 用 AES-256-GCM 加密原始值，按需还原。给模型用匿名值，给工具用还原值——完整往返，而不是单行道。

 跨会话稳定的身份

PERSON_1 在整段对话的每条消息里都是 PERSON_1。当 John Smith 分别出现在第 1、5、20 条消息里，模型每次看到的都是同一个占位符。它能追踪关系、引用前文、产出连贯的多轮输出——而从未看到真实 PII。会话可持久化到 SQLite（服务端）、IndexedDB（浏览器）或内存，身份映射在重启后依然有效。

 零信任，端侧运行

NER 推理通过 ONNX Runtime 在本地执行（量化模型约 280 MB）。不调用任何外部 API。可离线工作。PII 永不离开你的机器。

 关键能力

- 密钥而不只是 PII：除姓名、邮箱、电话外，还能检测 API Key（OpenAI、Anthropic、Stripe、AWS、GitHub 等）、JWT、私钥、数据库连接串和 .env 密钥。
- 机器翻译的语义增强：PII 标签上的可选性别和范围属性（、）为下游系统保留语法上下文。

 形状级识别器与默认关闭

有些识别器只要形状像敏感信息就会命中，在代码、命令与文档里误报率很高。Pi 扩展因此默认关闭这三类：银行标识码（BIC/SWIFT）、英国邮编、通用日期。需要它们时在配置里恢复：

json
{
  "rehydra": {
    "disableTypes": ["URL", "IP_ADDRESS"]
  }
}


即便显式启用，银行标识码仍要求值前 32 字符内出现完整的银行语境词（bic、swift、bank、银行、bankleitzahl），否则 8 位大写常量仍会被误判。

业务编号（CASE_ID）要求显式前缀词加分隔符且编号含数字，例如 Az. 2024/1234；裸结构（AB/1234、2024/1234）不再命中。

 环境文件与策略配置

.env 里只有敏感字段的值会进入全局已知值集合：项目名、端口这类普通配置值不会在后续文本里被替换。显式配置的 redactValues 按你的意图保留，不受这条筛选影响。

policy 里的集合类字段可以写成数组、阈值写成对象（程序化调用也可用 Set / Map）；字段类型不合法时启动会报错并指出字段名，不会静默丢掉保护规则。

 脱敏记录与本机查看页面

Pi 扩展默认逐请求记录脱敏结果，并启动一个只监听本机的查看页面：扩展收到什么、扩展输出什么，并排对照，命中明细与失败标记一目了然。

启动时终端会给出访问地址（例如 http://127.0.0.1:53211/），直接打开即可。页面左侧是记录列表（按会话/来源/类型/状态筛选、分页），右侧固定展示选中记录，打开即能看到首条内容；内容区可切换自动换行、查找与复制。清理入口在顶部，需要先选会话或明确清理全部，并二次确认。

详情按记录类型展示：上下文与工具结果记录给出"扩展收到的内容 / 扩展输出的内容"并排对照、命中明细与字段级对照；provider_request 记录展示发送前钩子采集的供应商请求体。该请求体来自宿主的 before_provider_request，只观察不改写，后续扩展仍可能改动载荷，也不代表网络发送成功或模型已接收。

记录写入 ~/.pi/agent/rehydra/records/records.sqlite（macOS/Linux 上目录 0700、库文件 0600；Windows 上权限位不生效，由用户目录的 NTFS 访问控制决定），最长保留 7 天、容量上限 300 MiB，先到者触发淘汰（超容量时淘汰最旧记录），单条快照上限 4 MiB。默认保存原文，因此真实值会明文落在本机磁盘上；不需要时关掉即可：

json
{
  "rehydra": {
    "record": { "includeOriginal": false },
    "dashboard": { "enabled": false }
  }
}


includeOriginal: false 时不保存任何前后文本，只保留类型、检测器、占位符、长度与偏移；dashboard.enabled: false 关闭查看页面。页面没有登录态，只靠浏览器同源约束限制跨站读取——本机其它进程仍能读到记录内容，请据此决定是否开启。

 地址识别说明
