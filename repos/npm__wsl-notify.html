README

skills



Reusable agent skills for opencode. Each skill is a directory with a
SKILL.md entry point (YAML frontmatter: name, description) plus optional assets/,
scripts/, and tests/.

At runtime everything a skill writes lives in one project-local workspace root, .pdca/ — helpers
it runs (.pdca/scripts/), cycle status files (.pdca/status/) and evidence
(.pdca//rv/). The skill's own scripts/ is the source of those helpers; the project runs
its copies from .pdca/scripts/.

 Contents

Skills live under skills/.

| Skill | Description |
| --- | --- |
| pdca | Single entry and base cycle of the family: one PLAN picks the form (Bounded Execution, incremental campaign or collection) and the coder/.NET specialized skill, then drives PLAN → DO → CHECK → ACT with independent verification, durable status, recovery and an honest STOP. |
| pdca-coder | Programming overlay applied to the chosen form (not a cycle of its own): adds code-specific criteria forms, toolchain discovery, command safety, evidence rules, security boundaries, parallel DO streams and the code CHECK deltas. |
| pdca-collection | Collection form: independent goals as separate complete PDCA invocations, coordinated through a preparation barrier, dependency groups, isolated lanes, an integration CHECK and one batch status; only done groups are merged, and incomplete work is preserved. |
| pdca-dotnet | .NET/C overlay that inherits pdca-coder and adds only the .NET differences: the dotnet toolchain, Roslyn-first symbol work, test host safety, coverage/mutation facts and .NET documentation conventions. |
| pdca-incremental | Incremental form: one goal whose method or volume is unknown advanced as credited steps on the base common contract — a preparation record, a comparable baseline, one accepted increment per step, one campaign status file and explicit stop conditions; a campaign can also be a campaign item of a collection batch and then stays sequential. |

Five skills, two layers. pdca is the only entry and carries the common cycle contract;
pdca-coder and pdca-dotnet are overlays (dotnet inherits coder) applied _to_ whichever form was
chosen, never a second cycle; pdca-collection and pdca-incremental are forms that inherit the
common contract and add only their container. The driver is the primary in normal mode or the cheap
pdca-orchestrator in autonomous mode; pdca-planner, pdca-executor, pdca-check, pdca-scout and
pdca-escalate carry the phases. Every CHECK is evidence-based, and a required approval that cannot be
obtained is a STOP rather than an open question.

 Install

Install a single skill with the skills CLI — one command per skill:

sh
npx skills add AlexeyShirshov/skills@pdca
npx skills add AlexeyShirshov/skills@pdca-coder
npx skills add AlexeyShirshov/skills@pdca-dotnet
npx skills add AlexeyShirshov/skills@pdca-collection
npx skills add AlexeyShirshov/skills@pdca-incremental


Add -g for a user-level install (all projects) and -y to skip prompts:

sh
npx skills add AlexeyShirs
