opencode-browser-tool

opencode 插件：Tauri 多 Webview 浏览器外壳 + 零注入视觉元素选取面板。对外只注册 2 个工具：bt_cli（命令行式分发器，内含 52 条浏览器自动化命令）与 bt_set_media_mode（摄像头/麦克风真伪切换），见下文「工具」。

 架构演进：V1-V3 使用 Playwright 注入式面板（存在弹框类元素无法批注的问题）；V4 改为 Rust Shell + 原始调试协议；V5 迁移到 Tauri 2 多 Webview（跨平台）。

 安装

jsonc
// opencode.json
{
  "plugin": ["@xiaoqiong0v0/opencode-browser-tool"]
}


 二进制获取（bt-shell）

插件依赖 Rust 外壳 bt-shell。默认在插件加载时（opencode 启动）就后台自动下载对应平台的 Release 资产到
~/.opencode/plugins-data/opencode-browser-tool//bt-shell[.exe]（Windows 即
%USERPROFILE%\.opencode\plugins-data\opencode-browser-tool\\bt-shell.exe），并就地覆盖同一路径
（不按插件版本建目录）；同目录另有 bt-shell.version.json 记录该可执行文件的来源
（tag / pluginVersion / asset / sha256 / size / downloadedAt / sourceUrl，src/binary.ts:69-79）。下载用 Release 的 SHA256SUMS 做
sha256 校验（幂等：sha 与当前 release 期望值一致即跳过；原子替换；跨进程 .lock；Linux 下载后 chmod 755）。下载在插件初始化时即发起、后台进行、不阻塞 opencode 启动（src/index.ts:859）；未就绪时工具调用会给出
明确提示（下载进度 / 失败原因），不会假装成功。

平台支持与系统依赖：

- Windows x64 → x86_64-pc-windows-msvc（WebView2，系统自带）
- Linux x64 → x86_64-unknown-linux-gnu，需系统库 libwebkit2gtk-4.1 / libgtk-3（及 appindicator / rsvg 等，见 docs/linux-support.md §5）
- 其它平台：暂不提供预编译，请用 BT_SHELL_PATH 指定自行构建的二进制

 代理：下载优先调用系统 curl（自动遵循 HTTPS_PROXY/HTTP_PROXY/NO_PROXY）；无 curl 时回退 Node fetch。

 本地开发/调试：插件优先使用本地 Rust 构建（按 opencode 传入的目录定位 rust/target/release，也支持 CARGO_TARGET_DIR、源码树的 /../rust/... 与 BT_SHELL_PATH）；选中的路径与来源会写进日志 Shell binary:  (source=local-dev|env|cargo-target-dir|download-cache)；找不到时自动回落下载缓存（普通用户不受影响）。

 版本与产物策略

- 中间位（minor）：只要动了 Rust / 要发新 exe，就升 x.Y.0（如 1.2.x → 1.3.0），并为该 x.Y.0 新建/更新 Release 挂上二进制。
- 末位（patch）：只改插件（TS/配置/文档，不改 Rust）时只升末位（如 1.2.0 → 1.2.1），不新发二进制。
- 二进制产物永远只挂在 x.Y.0 的 Release 上：插件的 patch 版本自动推导出对应的二进制 tag（把 patch 归 0）：插件 1.2.1 → 二进制 tag v1.2.0；1.3.0 → v1.3.0；1.3.0-beta.1 → v1.3.0。
- 因此纯插件改动升级时复用同一份二进制，不会重下；只有当推导出的 x.Y.0 与缓存中二进制的 sha 不一致（发新 exe）时才重新下载。
- 如需指向别的二进制发布（如临时验证），用 BT_SHELL_VERSION 显式覆盖——它表示二进制发布版本（形如 1.2.0），原样使用、不做归 0 推导。

 配置

配置文件：~/.config/opencode/browser-tool.jsonc（首次运行自动生成，默认值均为 en）

jsonc
{
  "panelLang": "en",
  "toolLang": "en"
}


项目级配置放 /.opencode/browser-tool.jsonc，会覆盖全局。

生成的配置还支持（可选项，见 src/config/index.ts:55-77,254-288）：

- browsersPath — 浏览器缓存目录（等价 BT_BROWSERS_PATH）
- cacheDir — 插件缓存根（默认 ~/.opencode/plugins-cache/opencode-browser-tool，下设 sessions//、user-data/、exports、tmp）
- nodePath — Node.js 可执行路径（等价 BT_NODE_PATH）
- disabledTools — 按已注册工具名禁用工具。bt_cli 合并后注册的工具名只有 bt_cli 与 bt_set_media_mode（src/index.ts:905-1004、过滤逻辑 src/index.ts:1034-1041），因此只有写这两个名字才生效；旧的按命令拆分的工具名（close、custom_user_agent…）或不带前缀的命令名不再有效、会被静默忽略（自动生成配置的注释示例同样偏旧，以本节为准）。禁用 bt_cli 等于没有命令入口，慎用。
- consoleBufferBytes / networkBufferBytes — console / network 日志流的字节预算，默认各 8 MiB（8 388 608，跨 tab 全局共享）；超出按最旧逐出并计入 dropped（等价 BT_CONSOLE_BUFFER_MB / BT_NETWORK_BUFFER_MB，env 以 MB 计）
- networkBurstWindowMs — network 聚合窗口，默认 2000 ms：仅当与上一条同 key 且间隔 ≤ 该值才累加 count（等价 BT_NETWORK_BURST_MS）
- consoleInject — Linux console 注入猴补开关，默认 Linux true / Windows false；Windows 走 CDP 不需要注入（等价 BT_CONSOLE_INJECT）
- webview2Args
