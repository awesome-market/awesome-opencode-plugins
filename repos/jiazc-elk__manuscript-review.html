正文审核器（Manuscript Review）

 给一幕/一个序列的正文和可选的前情/幕纲/人物卡/文风参考，让五个写作角色真的吵几轮，最后只交一份“好不好看、哪里不好看、怎么写更好”的报告。

 只读。不改稿。不碰你的文件。

 当前版本：0.3.0（beta）｜OpenCode / Claude Code / Codex 三端适配

 这是什么

正文审核器是一个面向已有正文的写作技巧审核 skill。它不写小说，不做设定，不生成大纲，也不做设定/逻辑/时间线一致性审查。它只做一件事：

 评价这一幕/这个序列/这一章写得好不好看，哪里不好看，有没有更好的写法。

它默认按一幕/一个序列审，而不是一章；因为单章看不出幕逆转、人物弧、求索、伏笔回收、跨章节奏。

 为什么不是“一个模型写一篇读后感”

单模型审稿有三个常见毛病：

1. 什么都夸/什么都骂：没有稳定标准；
2. 只挑逻辑错：设定、时间线、知识边界说一堆，却不告诉你“好不好看”；
3. 越改越像评审团：把作者的个人风格当成错误铲平。

这个项目用五个写作角色分工 + 多轮对抗 + 证据锚点 + “更好的写法”来解决：

- 场景、对白、描写、节奏各管一段，不越权；
- 人物角色看欲望/矛盾/声音/情感，不做人物卡一致性审判；
- 结构角色看幕功能/逆转/升级/章功能分布；
- 节拍拆解只画地图，不评好坏；
- 魔鬼红队问“这是真好看，还是‘有元素’？”；
- 主持负责最终裁定与报告。

 五个核心角色（+ 可选秘书）

| 角色 | Stable ID | 管什么 | 不管什么 |
|---|---|---|---|
| 场景、对白与描写 | scene_dialogue | 场景目标/转折、beat、对白行动、潜台词、人物声音、描写/POV、节奏、文字 | 幕结构、人物弧最终裁决 |
| 人物与情感 | character | 欲望、矛盾、压力选择、魅力、关系、情感落点、人物弧 | 设定/知识边界一致性 |
| 幕/序列结构与节奏 | story_plot_structure | 幕功能、激励、渐进复杂化、中点、危机/高潮、收束、章功能分布、节奏 | 人物心理、对白原文 |
| 节拍拆解 | story_deconstructor | 单位地图、章节功能、场景/beat、POV/情绪曲线、承诺/回收 | 评好坏、事实/逻辑核证 |
| 写作质量红队 | devil_critical_review | 钢人化、误报、虚高、建议副作用、共识偏差、单位是否足够 | 接管专业裁决 |
| 报告整合（可选） | secretary | 报告结构、算术、分歧保留 | 新增判断、改裁定 |

主持（Chairman）由主线程担任，不单设子代理。不派世界观/设定席。

 快速开始

 OpenCode

打开本仓库根目录，然后：

text
用正文审核器审第一卷第一幕（第1–8章）。
正文：/path/to/ch01-08/
前情：/path/to/前情摘要.md
幕纲：/path/to/第一幕幕纲.md
人物卡：/path/to/人物卡.md
目标：好不好看、哪里不好看、怎么改更好。


也可以显式点名 skill：manuscript-review，或使用 /manuscript-review 命令。

 Claude Code

打开本仓库根目录。Claude Code 会从 .claude/skills/manuscript-review/ 发现入口，从 .claude/agents/ 发现子代理。用法同上。

 Codex

打开本仓库根目录。canonical skill 在 .agents/skills/，子代理在 .codex/agents/。用法同上。

 安装到已有小说项目

1. 复制 .agents/skills/manuscript-review/ 到目标项目的同一路径；
2. 复制你所用宿主的适配层：
   - OpenCode：.opencode/agents/.md + .opencode/commands/.md
   - Claude Code：.claude/agents/.md + .claude/skills/manuscript-review/
   - Codex：.codex/agents/.toml
3. 重开项目/会话，让宿主重新发现 skill 与子代理；
4. 不要盲目覆盖目标项目已有的 AGENTS.md / CLAUDE.md；把本项目的“只读写作审核”规则合并进去；
5. 若目标项目已有同名 agent，先确认是否会冲突；必要时改成 review_scene 等名字，并同步修改 skill 里的 Stable ID 映射。

 审核单位：默认不是“一章”

| 单位 | 范围 | 能判 | 不能判 |
|---|---|---|---|
| 单章 chapter_local | 1 章 | 局部场景/对白/描写/节奏/本章功能 | 幕逆转、人物弧、求索、伏笔回收、跨章节奏 |
| 序列 sequence（推荐最低） | 3–8 章 | 序列目标/转折、章功能分布、局部弧、承诺/回收、序列节奏 | 全幕/全书弧、最终高潮 |
| 幕 act（推荐） | 约 8–30 章 | 幕功能、激励、渐进复杂化、中点、危机、高潮、收束、人物弧 | 全书/多卷 |
| 卷/多幕 | 多幕 | 跨幕结构、卷级弧、长线 | 全书终局（除非给全稿） |
| 序章/引子 | 1 章或短序列 | 建立缺失/悲剧/世界规则/悬念、交棒 | 主角弧、整幕逆转 |

只给一章时，审核器会先问“是否只做局部诊断”；不会把单章硬说成整幕。

 三种深度

| 模式 | 什么时候用 | 发生什么 |
|---|---|---|
| quick | 短序列、只想快速看 | 独立审 + 轻量收敛，3–5 条关键问题 |
| standard（默认） | 大多数幕/序列 | 独立审 → 交叉质询 → 收敛；两轮讨论 |
| deep | 卷末、高潮、关键转折、争议大的稿 | 再加一轮复核与魔鬼终检；逐章分析 |

深度 ≠ 审核单位：quick/standard/deep 决定讨论轮次；chapter/sequence/act 决定评审范围。

 报告里有什么

1. 审核摘要：审核单位/章节类型、总分、写作技巧分、好不好看、最该先改的三处、发布建议。
2. 审核范围与依据：素材状态、上下文覆盖、能判什么/不能判什么。
3. 单位地图：章功能表、场景/beat、POV/情绪曲线、承诺/回收。
4. 六维写作评价：场景与戏剧、对白与人物声音、描写与文字、节奏与可读性、人物与情感、幕/序列效果。
5. 写作技巧评分：10 项 1–5 分 + Craft Index。
6. P0/P1/P2 清单：每条带位置、证据、读者影响、改法。
7. 更好的写法：2–4 组“原文 → 可尝试 → 技法”，短句示例，不是代写。
8. 章节分布：逐章功能/强度/主要问题/局部分（只作诊断）。
9. 圆桌争议：谁和谁没谈拢、主持怎么裁、
