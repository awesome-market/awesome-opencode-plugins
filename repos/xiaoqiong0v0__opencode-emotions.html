opencode-emotions

OpenCode 插件：用极简英文命令（/angry 等）表达情绪，命令输出即带统一标注 emoji(等级/3)，让模型读到准确的情绪。零自然语言、免 i18n、无状态。
另含 TUI 插件：把「语音输入」识别出的文本 + 情绪，以同一套标注注入会话或输入框。
（早期的手动符号入口 !/?/.../666 已移除，见 docs/设计-情绪输入插件.md。）

 安装与生效

 推荐：opencode plugin（自动安装 + 改写配置）

bash
opencode plugin @xiaoqiong0v0/opencode-emotions            写入项目 .opencode/ 配置
opencode plugin @xiaoqiong0v0/opencode-emotions --global   写入全局配置目录


该命令会安装 npm 包，并按包内入口自动改写两处配置：server 入口 → opencode.json(c) 的 plugin，tui 入口 → tui.json 的 plugin。

 手动：在配置里写包名

server 插件（情绪命令）——opencode.json(c)：

jsonc
{
  "plugin": ["@xiaoqiong0v0/opencode-emotions"]
}


TUI 插件（语音输入 UI + 热键）——tui.json：

jsonc
{
  "plugin": ["@xiaoqiong0v0/opencode-emotions"]
}


改完重启 opencode 生效。

 需要先 npm install 吗？

不需要。opencode 启动时会按配置里的包名自动把插件安装到自己的包缓存（~/.cache/opencode/packages）。
npm install @xiaoqiong0v0/opencode-emotions 仅在你想在别处直接 import 本包时才需要。

 包内入口如何被解析

- server 插件 = 本包实际声明 exports["."] → dist/emotions.js（opencode 解析 server 入口按 exports["./server"] → main 回退；本包无 ./server 键，落到 main，同为 dist/emotions.js）；
- TUI 插件 = exports["./tui"] → dist/tui.js。

 依据（opencode v1.18.25 源码）：packages/opencode/src/plugin/shared.ts resolvePackageEntrypoint()、packages/opencode/src/plugin/loader.ts resolve()、packages/opencode/src/cli/cmd/plug.ts（opencode plugin 按 exports["./server"]/main/exports["./tui"] 判定要写哪些配置）。

 依赖体积（含 ffmpeg-static）

- ffmpeg-static（写在 optionalDependencies）：npm 安装时由该包的 install 脚本下载一个预编译 ffmpeg 二进制到 node_modules/ffmpeg-static（Windows ffmpeg.exe 实测 ≈ 79 MB），用于语音采集（及 Termux 分块录音转码）。云 TTS 走流式 raw PCM，不再用它转码。代价是首次安装的网络流量与磁盘占用。不依赖系统 ffmpeg（非 Termux 下不读 PATH）：需要自备时用环境变量 FFMPEG_BIN 指向任何可用 ffmpeg，且必须通过 ffmpeg -version 真执行校验才会被采用。
- opencode 自动安装不会执行 install 脚本（源码 packages/core/src/npm.ts 硬编码 ignoreScripts: true）⇒ 插件缓存里只有包文件、没有 ffmpeg.exe。语音入口在枚举设备前做启动自检（非 Termux 每次都执行）：把 ffmpeg-static 二进制补齐 —— 先拷贝同机可用副本（离线、零下载），没有副本才用当前 Node 跑 ffmpeg-static/install.js 下载（约 30–80MB，需 GitHub Release 可达，默认超时 120s）；补齐结果一律用 ffmpeg -version 真执行校验（不再只看文件存在）。离线/内网用 FFMPEG_BIN 指向可用 ffmpeg。node scripts/ensure-ffmpeg.mjs 仍是发布前门禁/离线预取（--check 只检查，缺失退出码 1），与运行时共用同一实现。
- ffmpeg-static 自身按 GPL-3.0-or-later 分发（与本包 MIT 许可相互独立）。
- ws：ASR/TTS 的 WebSocket 客户端（体积小）。

 只用情绪命令、不用语音的用户：ffmpeg-static 位于 optionalDependencies，安装失败（如部分 Termux 环境）不会拖垮主装；opencode 自动安装的是生产依赖并跳过 install 脚本，见上一条的补齐步骤。

 用法：情绪命令

消息以 / 触发命令，命令输出即为标注（可接你写的正文）：

| 命令 | 标注 |
|---|---|
| /annoyed | 😠(1/3) |
| /angry | 😡(2/3) |
| /furious | 🤬(3/3) |
| /confused | 🤔(2/3) |
| /speechless | 😑(2/3) |
| /neutral | 😐 |
| /ok | 🙂(1/3) |
| /happy | 😊(2/3) |
| /great | 🤩(3/3) |

例：/angry 需求又改了 → 😡(2/3) 需求又改了；无参数时只产生标注本身（/great → 🤩(3/3)）。

 早期的手动符号入口（!/？/.../666）已移除：语音来源已能自动给出情绪，符号冗余且有误伤（? 这是什么、666 元）与硬限制（行首半角 ! 被 shell 模式拦截）。原因与影响见 docs/changes/设计-情绪输入插件.20261014.md。
