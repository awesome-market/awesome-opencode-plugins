README

Local Project MCP

Install once for OpenCode. When you open a project, Local Project MCP automatically finds the nearest mcp.json and makes that project's local and remote servers available as native OpenCode MCP connections.

The plugin adds those server definitions to OpenCode's in-memory configuration for that project session. OpenCode runs local commands, connects to remote servers, manages OAuth, and exposes their tools. There is no MCP bridge, launch wrapper, configuration sync, background watcher, or project-specific OpenCode file to maintain.

This release targets OpenCode 1.19.4. OpenCode's v2 plugin API and mcp.servers configuration have different shapes and are not supported by this release.

 Install

Install the v0.1.1 GitHub release globally using OpenCode’s native plugin installer:

sh
opencode plugin --global https://github.com/autobelay/opencode-project-scoped-mcp/releases/download/v0.1.1/autobelay-opencode-project-scoped-mcp-0.1.1.tgz


OpenCode 1.19.4 uses opencode plugin  -g for a global install; opencode plugin add belongs to the separate v2 CLI. An alternative that uses the documented global plugin directory is to copy the built, dependency-free dist/plugin.js to ~/.config/opencode/plugins/project-scoped-mcp.js. OpenCode 1.19.4 auto-discovers .js and .ts files in that directory; it does not auto-discover .mjs there.

Start OpenCode in a project with a manifest:

sh
cd /path/to/project
opencode


Ask: “Use project_mcp_status to show this project's MCP connections.” The tool returns the title “Local Project MCP · Status,” which OpenCode records in its structured tool event. Native MCP tools are available separately under their generated server IDs. OpenCode 1.19.4 uses those technical IDs for native tool calls; this plugin cannot relabel their titles through its supported hooks. No project path is stored in the global installation.

 Why project-scoped tools?

An MCP server may need a particular checkout's files, branch, design tokens, or credentials. Keeping its declaration with the project lets the configuration travel with that code. A user installs this plugin once, while each project can declare its own servers without copying entries into the user's OpenCode configuration.

Local Project MCP uses OpenCode's plugin config hook before native MCP connections initialize. The project manifest is read at that point. Changes to mcp.json take effect when the project is loaded again, such as in a new OpenCode process.

 Example: a design assistant for one application

Imagine a fictional field-notes application. Its design MCP could know the current checkout's palette, spacing, component variants, unpublished screen references, and navigation conventions. Its tools might read design tokens or explain the layout of a component. These assets and conventions belong to one application; publishing a generic public MCP would not supply them.
