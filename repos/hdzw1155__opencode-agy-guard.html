opencode-agy-guard




把本机 agy（Google Antigravity CLI）接入 OpenCode V2：底座来自 dsh-agy-safe 的 agy CLI 接入方式，核心是作者独立设计的跨进程限流器（与 4–5 个 AI 协作实现）。

 这是一个工具插件，不是模型提供商：主模型不变，需要时由主模型调用 agy 工具把任务交给本机 agy。agy 的模型不会出现在 OpenCode 的「管理模型」列表里；想让它出现在模型选择器，需要另外实现 provider 桥。

 搜「agy 封号」「Antigravity 429」「OpenCode 并发」找到这里？ 直接看下面的「限流器」一节和 guard 配置。如果你正被 429 / 风控困扰，先把间隔、每日上限和队列上限调保守。

 English: A local OpenCode V2 tool plugin that exposes your own agy CLI as a helper tool. The agy CLI adapter is based on dsh-agy-safe; the rate limiter is the author's original design, built in collaboration with several AIs. This is a tool plugin, not a model provider: agy models do not appear in OpenCode's model picker. Not affiliated with Google, Antigravity, or OpenCode. Built with AI assistance; review the code before trusting it. Use at your own risk.

 免责声明： 非官方项目，与 Google / Antigravity / OpenCode 均无关。它只调用你本机安装的 agy，不代替登录、不绕过配额和风控，也不代理或转售 Google AI 服务——每个使用者运行自己的 agy 和自己的账号。你需要自己的可用账号和网络环境，并自行承担 Google 服务条款、账号风控与本机权限风险。默认 yolo: true 会传 --dangerously-skip-permissions，agy 能读写 dir 里的文件、执行命令；建议只做只读或低风险任务。限流器降低频率风险，但不构成任何账号安全保证。

 AI 声明： 本项目由人类提出需求、定义边界、设计限流规则并做最终验收；代码、测试和文档主要由 AI（OpenCode 智能体 / DeepSeek V4.1 Flash）编写。限流器的方案来自作者本人，AI 负责协助实现与测试。请在依赖它之前自行审阅代码，重点看 src/guard.js（限流逻辑）和 src/runner.js（怎么调用 agy）。

 先搞清楚：工具插件 vs 模型提供商

| | 工具插件（本项目） | 模型提供商（不是本项目） |
| --- | --- | --- |
| 模型选择器 | 不出现 | agy 的模型会出现在列表里 |
| 谁在回答 | 主模型不变；它按需调用 agy 工具 | 选中后整个对话由 agy 生成 |
| 工具历史 | OpenCode 工具照常工作 | 现有 V1 桥会丢失工具历史 |
| 本项目形态 | agy / agy_status 两个工具 + /agy、/agy-status 两个命令 | 需要额外的 provider 桥，尚未实现 |

一句话：agy 是主模型手下的一个“外援工具”，不是替换主模型。

 这个项目的构成

| 部分 | 来源 |
| --- | --- |
| agy CLI 接入底座（stream-json / NDJSON / host tool 协议思路） | dsh-agy-safe（MIT） |
| 限流器设计：1 并发、≥1.5s 间隔 + 抖动、10 次/60s 滑动窗口、500 次/日、连续失败或 429 熔断、半开探测、排队超时 | 作者原创，与 4–5 个 AI 协作实现 |
| OpenCode V2 工具/命令适配、模型自动同步、agy_status、超时/传输重试、测试与 CI | 本项目 |

dsh-agy-safe 只提供底座，上游没有限流器。限流器最初是作者的 DSH 个人补丁，本项目把它移植到 OpenCode，并重写、修正了半开探测泄漏、UTC 日期、非原子写入等问题。

 特性

- 限流器（本项目核心）：作者原创设计——跨进程全局串行（文件锁）+ 有界等待队列 + 最小间隔 + 滑动窗口 + 每日上限 + 熔断/半开 + 排队超时，降低触发 429 / 风控的概率。
- 工具形态，不是 provider：不注册模型、不接管对话、不丢工具历史；agy 只负责你交给它的那一段任务。
- 本地 CLI：直接调用本机 agy 的 headless stream-json 协议，不经过任何第三方 HTTP 服务。
- 模型自动同步：启动时从 agy models 拉取当前模型列表，支持友好别名和原始 ID。
- 可观测：agy_status 查看状态、reset 清除熔断；超时/传输失败自动重试一次。
- 零依赖：纯 ESM JavaScript + Node 内置模块，npm test 即可跑测试。

 底座与设计取舍

dsh-agy-safe 提供的是 agy CLI 的接入底座。OpenCode V2 没有等价的“进程内自定义 provider + 宿主工具回调”插件 API；现有的 @ichisay/opencode-agy-plugin 是 V1 的 AI SDK provider，会把 OpenCode 的工具历史丢掉，而且每次调用都跳过权限，不适合直接搬到 V2。

所以本项目保留底座、换成更窄的形态：把 agy 当成一个独立的 helper/subagent 工具，工具执行和权限由 OpenCode 自己负责，把主要精力放在作者原创的限流器和 OpenCode V2 适配上。

 环境要求

- OpenCode V2（在 v2.0.32 上测试）；
- Node.js = 20；
- 已登录、可用的 agy CLI（在 1.4.2 上测试）；
- 能正常访问 Antigravity 的网络环境。

 安装

1. 确认 agy 在 PATH 中，或设置 AGY_PATH：

   powershell
   Get-Command agy
    可选
   $env:AGY_PATH = (Get-Command agy).Source
