opencode-claude





 [!NOTE]
 This is a maintained fork of @openchamber/opencode-claude, which is archived. OpenChamber 2.8 also removes the original package from managed configs automatically.

 OpenCode now has a built-in Claude Code provider. This fork stays alive until that provider covers everything this plugin does, including working with context-management plugins such as Billion Context. If the built-in provider already does what you need, use it instead.

 To switch from the original, replace @openchamber/opencode-claude with @bernhardberger/opencode-claude in plugins. The provider ID (claude-code) and model IDs are unchanged, so saved model selections keep working. Fork changes are in the changelog.

Use your Claude Pro or Max plan in OpenCode and OpenChamber.

The plugin adds a Claude Code provider. Pick Opus, Fable, Sonnet or Haiku in OpenCode like any other model, and every request runs through the official Claude Agent SDK on top of the claude CLI installed on your machine. No API key, and the plugin never touches your Claude credentials.

This is an independent community project. It isn't affiliated with, endorsed by, or supported by Anthropic. Claude and Claude Code are trademarks of Anthropic.

 Setting this up with a coding agent? Point it at docs/agents.md. The page has step-by-step instructions, checks and rules written for agents.

 Why this fork exists

OpenChamber archived @openchamber/opencode-claude once OpenCode shipped its own Claude Code provider. For many setups, the built-in provider is the right choice. Ours wasn't ready to move yet, for three reasons (as of OpenCode 2.4.0 and Billion Context 0.1.216):

- Context plugins don't work with the built-in provider yet. Billion Context tracks each conversation by its OpenCode session ID (ses_…). The built-in provider sends Claude Code's own session UUID instead, so Billion Context can't link its state to the chat. acp_status fails with "no ACP state for this session yet" (billion-context7582, fix in review). Its other context tools look up sessions the same way. Routing the built-in provider through the Billion Context proxy (billion-context6819) is merged but not in a stable release yet. With this plugin, requests go through OpenCode's normal provider path, where Billion Context already tags them with the OpenCode session ID, so these tools work today.
- The original package had a cache bug with Billion Context. Billion Context appends a status footer to the latest message, and the footer changes every turn. The original plugin treated that as an edit to the history and replayed the whole chat into a fresh Claude session, which threw the prompt cache away. On a plan, that cost shows up directly in your usage limits. The fix is in this fork's 1.7.1 release.
