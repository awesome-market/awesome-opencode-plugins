README

@dan-ai-studio/dshopencodego

让 DeepSeek Harness 正常使用 OpenCode Go 订阅：模型列表直接来自网关，且每个推理请求都携带网关要求的 x-opencode-session。

English

 为什么需要它

原生 DSH 已经能连 OpenCode Go（llm-pi-ai 内置该 provider）。本插件补的是它不提供的那几件事：

| 能力 | 原生 DSH | 本插件 |
| --- | --- | --- |
| 实时模型目录 | 构建期快照：pi-ai 打包时生成的固定表，网关新增模型要等 pi-ai 发版 | 实时读取网关目录，多级回退 + TTL 缓存 |
| 额度窗口（5 小时 / 本周 / 本月） | 无 | ✅ |
| 花费估算 | 无 | ✅ |
| 逐模型开关 modelVisibility | 无 | ✅ |

本插件为 opencode-go 路由提供自己的适配器，并提供用量与设置界面。

 关于会话头：Go 要求每个请求带稳定的 x-opencode-session，缺失即 400 MissingSessionID。这一项曾是本插件的原始存在理由，但 pi-ai 已于 2026-09-09（561a2e06）实现注入、llm-pi-ai 自动携带，因此原生 DSH 现在也不会缺会话头。本插件当前仍保留自己的实现（为缺失会话 id 的请求提供一次性 UUID 兜底），待该兜底进入上游后再收缩——评估过程见 docs/scope-review-2026-10.md。

 安装

前提：DSH 0.2.0 系列（0.2.0-rc.1 及之后，见「兼容性」）；Node ^22.19.0 || =24.0.0；dsh 与 pnpm 可用。

 路由互斥：同一个 profile 里 opencode-go 只能由一个适配器提供。装本插件前请先卸载旧插件（dsh plugin --profile  remove @dan-ai-studio/dsh-opencode-go），或清空 llm-pi-ai 配置里名为 opencode-go 的 provider。否则插件会记录一条明确的占用诊断，路由不会注册（其余功能照常）。

 桌面端用户：DSH 桌面端不走命令行安装，安装、升级与卸载都在应用内 Plugins 页完成，见文末「桌面端（Electron 应用）」。

 方式一：npm（推荐）

sh
dsh plugin --profile web add @dan-ai-studio/dshopencodego@


安装后确认真实加载——--dump-config 证明不了这一点：

1. 启动输出里应出现插件自己的注册日志 dshopencodego: route "opencode-go" registered as OpenCode Go（enabled: false 时是 dshopencodego: disabled by configuration; …）。没有它就没加载——被版本门禁拒绝时，同一条输出流里会打印 Plugin … is incompatible with dsh …。
2. 没有 HMR 的 profile 安装后会回报 restart-required（restartReason: no-hmr）：重启 DSH 后插件才生效。
3. 日志位置：启动失败会把完整诊断写到 $DSH_HOME/logs/startup--.log 并打印该路径；dsh plugin 失败会打印 dsh: plugin command failed; diagnostics: （profile 下的 .plugin-manager/logs/operation-/pnpm.log）。
4. 会话头是否真的发出去了：node tools/verify/live-check.mjs --check-only 是零成本本地预检，会打印本次将会携带的 x-opencode-session 与 x-session-affinity；去掉 --check-only、加 --allow-live 才会真发一次最小请求（花钱，规则见 tools/verify/README.md），脚本随后断言并打印 OK x-opencode-session: 。

 dsh --profile web --dump-config | grep dshopencodego 不构成加载证据：被门禁拒绝的插件行同样会出现在 dump 里（packages/boot/app-boot/README.md）。它只能证明"这一行被写进了组合"。

 方式二：GitHub Release

sh
dsh plugin --profile web add https://github.com/dan-ai-studio/dshopencodego/releases/download/v/dan-ai-studio-dshopencodego-.tgz


 方式三：本地构建

sh
npm ci
npm run build
npm pack
dsh plugin --profile web add ./dan-ai-studio-dshopencodego-.tgz


 用本地路径安装 tarball。把远程 tarball URL 装进一个已有缓存的 profile 会撞上 pnpm 的 ERR_PNPM_MISSING_TARBALL_INTEGRITY（见「故障排查」）。

 升级与卸载

sh
dsh plugin --profile web add     升级
dsh plugin --profile web remove @dan-ai-studio/dshopencodego    卸载


 pnpm 对同名本地 tarball 会静默复用旧内容（added 0）。升级本地构建时请改文件名再装。

 桌面端（Electron 应用）

DSH 桌面端是 Electron 壳 + 完整的 dsh Web 应用，本插件对它同样适用：host 半边是标准 bundle patch，client 半边声明的平台就是 web——桌面端渲染的正是这套 Web 客户端，设置页分区与会话内用量按钮来自同一批客户端包。桌面端使用自己的 profile $DSH_HOME/profiles/desktop，与 profiles/web 互不共享：凭证、模型可见性与插件设置都要在桌面端重新配一次。

安装必须走应用内界面，不要使用上面的 dsh plugin 命令：

1. 打开桌面端 → 设置 → Plugins（插件） 页；
2. 安装规格填 @dan-ai-studio/dshopencodego（或指定版本，如 @dan-ai-studio/dshopencodego@0.1.11），确认安装；
3. 按提示重启应用，再到设置页填 API Key（引用名 OPENCODE_GO_API_KEY）。
