Keel · 龙骨

 别写文档。让文档读代码。

新会话、新同事、新 AI 接手时，你又要讲一遍项目规则——因为上一轮的解释留在聊天记录里，不在仓库里。

大多数「项目文档」其实是第二份代码：手写在 md 里，代码一改它就过期。Keel 把规则、组件、接口、Wiki 四页改成直接读仓库里的那一份源文件。

不是写得更勤，是让文档不再有第二份。页面没有副本，也就没有过期。

同一个页面，两拨读者。给内部人看时，那个还没登记的组件、以及它躺在哪个文件里都在；对外时这些整体消失——页面还是那个页面，代码还是那份代码。让它消失的不是开关，是构建期剔除和接口鉴权。

 30 秒，什么都不用装

看效果 → 打开在线演示，右下角对照「完整视角 / 对外视角」。那个开关是演示专用的，真实项目里不该有。想离线看也行：下载单文件 双击即开，断网可用。

量项目 → 只读，只告诉你缺什么，一个字节都不改：

bash
git clone --depth=1 https://github.com/Chaierss/keel keel-tmp
node keel-tmp/skills/keel/scripts/console-check.mjs --root .


装上 →

bash
npx skills add Chaierss/keel -g


任何认 SKILL.md 的 agent 都能用：Claude Code、Cursor、Codex、Windsurf、Trae、WorkBuddy。手动安装路径见 docs/publishing.md。

 换个 AI 接着写。它把「专注模式」理解成「全屏、无干扰」，而在你团队里，这个词指的是「只显示当前任务那一块」。

 你解释了一遍，它写对了。下次开新会话，又错了。

---

 发版前安全同事问：「有硬编码密钥吗？」

 你说没有。然后 git log 里躺着一个 .env。

三个事故长得完全不一样，根因是同一个：真相在某个人的记忆里，不在仓库里。

 四页，四个真相源，零个副本

一个页面只有同时满足三件事才算「不会过期」：真相源在仓库里、页面只读它、改它不需要第二步。缺任意一条，你就又写了一份会过期的文档。

| 页面 | 唯一真相源 | 凭什么不落后 |
|---|---|---|
| 规则 | keel/rules.json | 页面直接读这个文件；同一份还能导出 Markdown 喂给 AI |
| 组件 | keel/components.json + 目录扫描 | 注册表说「批准了哪些」，目录说「实际有哪些」，对不上就报 |
| 接口文档 | 框架生成的 OpenAPI | 不存在手写接口清单，也就没有可落后的东西 |
| Wiki | docs/wiki/.md | 直接挂仓库文件，无缓存、无搬运 |

!数据流：仓库源文件 → 设置页 → 可见性边界 → 发版门禁

每一页做到什么程度才算完（这不是装饰，是四页的分工）：

| 页面 | 只有一句话不行 | 做到这个程度 |
|---|---|---|
| 规则 | 模板只给两条示例 | 15 条规则 + 4 个页面形态 + 8 条术语，每条带「识别信号 / 代码落点 / 不要怎么叫」；agent 还能扫代码归纳出候选，人点头才入档 |
| 组件 | 一个默认态截图 | 真实渲染 + 变体 × 状态矩阵，每格标出生效的 props；未登记、零引用自动进告警与待下架 |
| 接口文档 | 一列接口名 | 左分组 / 右详情（写踩坑点，不复述字段名）/ 下试调（显示当前身份与 scopes） |
| Wiki | 一篇概述 | 代码地图 + 引用式内联核心实现，按源文件真实行号渲染，源码改了页面跟着变 |

 装完之后怎么用

在项目里说一句「给这个项目装 keel」，agent 会读 SKILL.md 按开荒 + 五步走。你也可以照单执行：

| 步 | 做什么 | 产出 |
|---|---|---|
| 0 | 开荒：登记顶层目录、写 agent 入口、定目标与里程碑 | AGENTS.md / structure.json / project.json |
| 1 | 定边界：四问写清——哪些产物带它、谁能打开、哪些字段不能给 | 一份可定位的边界声明 |
| 2 | 建骨架：先定每页读哪个文件，再写页面 | rules.json / components.json / wiki.json |
| 3 | 逐页实现：规则 → 组件 → 接口 → Wiki（顺序有讲究，规则定术语，后面三页才有共同语言） | 四个 tab |
| 4 | 挂门禁：脚本进 CI | 一条 workflow |
| 5 | 发版前预检：先扫、后发 | 绿灯才打 tag |

日常只有两条命令：

bash
node keel/console-check.mjs --strict      19 项检查：四件套齐、目录与里程碑对账、没有未登记组件
node keel/preflight-scan.mjs --strict     17 条代码模式规则 + 文件级与产物级检查


不想一次做完？references/quickstart.md 是 15 分钟最小版，只装规则 + 组件，接口文档先用现成的 Swagger 顶。半套也比分叉强。

 关于升级：不能自动升级，这是设计不是偷懒。技能本体重新 npx skills add 会覆盖更新；你项目里的 keel/ 是拷贝制——里面的 rules.json、组件登记、目录配置都是你的项目事实，整目录覆盖等于把它们冲掉。

 所以改成对账：console-check 的 VER-01 每次都告诉你「模板版本 1.0.1，当前技能 2.2.1」，然后你照 references/upgrading.md 的版本区间逐条改。它是 warn 不是 error——升级提醒不该让 CI 变红。

 门禁只报机器能确定的事

console-check 的分级标准是「机器能不能证明」：文件不存在、规则 id 重复、注册表指向空——error；组件零引用、文档太短——warn。它不假装知道判断不了的事，而且把「扫到 0 个文件」判成 error——空扫描给的绿灯比红灯更危险。

preflight-scan 覆盖私钥入库、硬编码凭证、云厂商密钥格式、动态执行、命令注入、不安全反序列化、关闭证书校验、XSS 注入点、调试残留、CORS 通配、SQL 拼接、默认口令、鉴权绕过、路径穿越、SSRF，外加一个每条豁免都必须写原因的 .preflightignore。

两个脚本都不替代渗透测试。它们的存在，是为了让最便宜的那 80% 到不了线上。
