README

opencode-cache-manager








  


An OpenCode plugin for managing your prompt cache. Keep the cache of idle sessions warm with hidden pings so they don't expire while you're away. The TUI gives you a way to visualise your cache state and savings from your cache keepalive runs. This plugin is highly configurable and especially tuned for Claude and OpenAI GPT-5.6+.

Pick a cache TTL per session (5 minutes, 1 hour, or a hybrid of the two). Pings are timed to land just before it expires.


  


 Quickstart

sh
opencode plugin add @noppu-labs/opencode-cache-manager


 Supported models

- It works with Claude and OpenAI models through their official API or through proxies such as OpenRouter or OmniRoute (via Anthropic Messages API or OpenAI-compatible endpoints).
- It can work with other models as long as they support Claude/OpenAI style of cache breakpoints, with some additional configuration.
- For incompatible/unconfigured models (e.g. older GPT, Gemini, or DeepSeek), the plugin shows how much of each prompt was cached and performs no keepalive mechanics (because you'd get no benefit from it).

 Why

OpenCode marks Claude's cache breakpoints on its own (tools, system prompt, the last message) but always sends ttl: "5m", and there is no config option for it. Step away for ten minutes and your next prompt writes the whole context into the cache again at 1.25x the base input price (2x for the 1h cache) instead of reading it at about 0.1x. GPT-5.6+ has the same problem: OpenAI caches for 30 minutes on its own, and the 12-hour cache has to be requested per breakpoint, which OpenCode never does.

This plugin rewrites the outgoing request after OpenCode's own cache policy runs, so you can switch a session to the long-lived cache (1 hour on Claude, 12 hours on GPT-5.6+) without forking the provider package. Keepalive handles the other half: it sends a small ping shortly before the cache would expire, so the context is still cached when you come back.

Published to npm under two names with identical contents: @noppu-labs/opencode-cache-manager and opencode-cache-manager.

 The three modes

The modes are named after Claude's cache TTLs; Modes per provider maps them onto OpenAI's. On Claude:

| Mode           | Tools + system | Messages     | Write cost       |
| -------------- | -------------- | ------------ | ---------------- |
| 5m (default) | 5m ephemeral   | 5m ephemeral | 1.25x base input |
| 1h           | 1h ephemeral   | 1h ephemeral | 2x base input    |
| hybrid       | 1h ephemeral   | 5m ephemeral | mixed            |
