BGE-M3 migration

An experimental Japanese-memory calibration used the following local settings.
These are corpus-specific operating points, not universal model defaults.

jsonc
{
  "embeddingModel": "Xenova/bge-m3",
  "embeddingDimensions": 1024,
  "embeddingPooling": "cls",
  "embeddingDtype": "q8",
  "similarityThreshold": 0.375,
  "chatMessage": { "maxMemories": 3, "similarityThreshold": 0.41 },
  "updateOnCaptureSimilarityThreshold": 0.7,
  "dreaming": { "relatedThreshold": 0.725 },
}


Back up the store before changing models, then use the Web UI's re-embed
migration rather than a fresh start.
Migration detects model-name changes even at the same dimension, rebuilds
content/tag vectors and profile centroids, and preserves session links, pins,
and trash timestamps.
After switching models in an already-running host, restart the OpenCode service
once: the process-wide embedding singleton can otherwise retain the previous
model across a plugin reload, even when migration detection shows the new model.
The auto-injection cutoff was evaluated with a three-memory cap and usefulness
judgments.
The separate 0.375 explicit-search cutoff used a ten-memory cap and retained
430/451 retrievable known-source targets in 489 synthetic test queries.
This is source-target recall, not human usefulness precision, and does not
validate cross-project search.
Duplicate detection and profile matching still need separate calibration.

A persistent memory system for AI coding agents that enables long-term context retention across sessions using local vector database technology.

 Core Features

- Local database: embedded Turso/libSQL with native vector search, stored under storagePath. No separate vector database.
- Intelligent prompt-based memory extraction (auto-capture): when a session goes idle, a background AI request turns the technical work into persistent project memories.
- Automatic recall: relevant memories and the user profile are injected into the model's context (chatMessage).
- User profile learning: a cross-project summary of your preferences, patterns and workflows.
- Memory hygiene: smart deduplication, optional update-on-capture, and optional dreaming consolidation with recoverable trash.
- Multi-provider AI support: any provider configured in OpenCode (opencodeProvider / opencodeModel), or a manual API: OpenAI Chat Completions, OpenAI Responses, Anthropic, MiniMax, OrcaRouter, Atlas Cloud, Cheaper Inference, API Route, Runcrate, CloudGPU.
- Embeddings: 12+ local embedding models on CPU (no GPU needed) or any OpenAI-compatible embeddings API.
- Full-featured web UI: unified memory–prompt timeline, user profile, skill library, Markdown vault and health stats, with optional HTTP Basic Auth.
- Privacy:  tags, credential redaction before capture, and optional encryptio
