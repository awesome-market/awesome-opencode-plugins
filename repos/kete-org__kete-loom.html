Kete Loom

Curated, tested Agent Skills, subagents and commands for coding agents.
One source. Installs unchanged in Claude Code, Codex, OpenCode, Cursor, Gemini CLI, GitHub Copilot, Kete Code and Kiro.

---

Kete Loom is the skills library behind Kete Code. It ships skills (folders the agent loads when relevant), agents (subagents it delegates to), commands (slash commands you type), rules (short always-on guidance), hooks (checks that run around the agent's tool calls and when it finishes) and MCP server configs. It takes a quality-first approach: fewer items, and every one of them is

- portable: uses the strictest common subset of the Agent Skills format, so no host rejects it;
- tested: skills and agents ship trigger evals that check they load for the right requests and stay out of the way for the wrong ones, and the discipline skills add behaviour evals that check the agent actually follows them under pressure, compared with a run without the skill;
- short: under 300 lines, with detail moved into references/ that the agent reads only when needed;
- versioned and labelled: semver, category and a risk level (read-only, writes-files, runs-commands, network) in its metadata;
- script-backed where the work is deterministic.

 Install

 Any agent (recommended)

bash
npx @ketecode/loom install


This installs every skill into ~/.agents/skills (read by Codex, OpenCode, Cursor, Gemini CLI, GitHub Copilot and Kete Code) and ~/.claude/skills (Claude Code). Agents and commands go into ~/.claude/agents and ~/.claude/commands (read by Claude Code, and for agents also Cursor and VS Code Copilot), and into Codex, OpenCode, Gemini CLI, Kete Code and Kiro's own folders when those hosts are installed (Kiro also gets its own copy of the skills). Each agent and command is converted to the format its host expects. Restart your agent afterwards.

Or pick a profile instead of installing everything:

| Profile | What it installs |
|---|---|
| minimal | Test-first work, verification, security review, code review |
| core | The essentials, planning, git, onboarding and session handoff, plus the language and framework packs your project uses (detected from package.json, go.mod, pyproject.toml, Cargo.toml, Dockerfile and so on) |
| developer | core plus the four safety hooks |
| strict | developer plus the opt-in guardrails: read before edit, protected lint configs, background dev servers, staying in the worktree, no secret reads or planted instructions, warnings about injected text in what it reads, no accidental file truncation, a warning before the context fills up, valid commit messages, and no unfinished stubs or failing lint and type-check at the end |
| method | A full development method: design before code, granular plans, a fresh subagent per task with spec and q
