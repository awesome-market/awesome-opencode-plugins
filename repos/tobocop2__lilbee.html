README

The whole local AI stack in one executable: it runs and manages the models, and searches everything you own with them.

Project site &nbsp;·&nbsp; Tutorial reels &nbsp;·&nbsp; PyPI &nbsp;·&nbsp; Obsidian plugin &nbsp;·&nbsp; REST API &nbsp;·&nbsp; Chat (lilbee)

lilbee runs your models and puts them to work as a search engine you can talk to. It searches your files, notes, code and saved web pages, and every answer cites its source, down to the line or page. It also crawls websites into your library, launches your coding agents on local models, and gives any MCP-aware agent cited answers. Ask in plain English.

It is private. Your files, the index and your questions stay on your machine. No telemetry, no account. lilbee contacts a cloud provider only when you set its API key.

Prefer a GUI? The Obsidian plugin puts lilbee's model manager and search inside your vault, with no terminal needed.

!ask lilbee "what is lilbee in one sentence?" and get a cited answer drawn from its own README

 Tutorial reel: every demo on this page and more, with long-form captions, at lilbee.sh/tutorial.

 Beta software. lilbee is in active beta. Every PyPI release is a pre-release, so pip needs --pre and uv needs --prerelease=allow. Commands and on-disk formats can change between betas. Bug reports are very welcome; that's the whole point of the beta. Latest pre-release: lilbee on PyPI.

 Why lilbee

A small local model is fun, but limited on its own. Give it properly processed documents and a search engine over them, and it becomes genuinely powerful. Without those, it never gets past novelty.

lilbee is built for consumer hardware and for people who don't want to babysit infrastructure. It isn't another model server you point an app at; it's a local search engine with the model runner built in.

- Install one file. Talk to your stuff. Most ways to chat with your documents locally mean Docker, a separate model server, a database service and a browser tab. lilbee needs none of them. Point it at a folder, and local AI is useful from the first question.
- A search engine with proof. On MS MARCO (8.8M passages, 6,980 real queries), lilbee's general-purpose pipeline scores MRR@10 0.365. That is above ColBERT, a system trained only for that test. Few local tools publish a retrieval score for their own pipeline at all. See the benchmark.
- Native speed underneath. Models run in [llama.cpp] (C and C++). The index, the document reader, the crawler and the code parser are Rust ([LanceDB], [Xberg], [crawlberg], [tree-sitter]). [Nuitka] compiles lilbee itself into one native binary.
- Runs on what you have. Native executables for macOS, Linux and Windows, with Metal, Vulkan, CUDA and ROCm builds, and a build for CPUs from before 2013. One command on Homebrew, Scoop, AUR, Nix, Flatpak, Snap, npm, PyPI or Docker. Smaller than LM Studio everywhere, and than Ollama on Windows and Linux,
