DragonAPI in Magpie

把 DragonAPI 接进 magpie：模型广场、余额、用量，外加一个能按分组建钥匙的本地界面。

 当前版本 0.3.0。只做供应商插件 + 只读看板 + 密钥管理，不做「页面里点充值」。

 它是什么

一个独立的 magpie 插件包，同时是两样东西：

| 身份 | 作用 |
| --- | --- |
| 供应商插件 | 把站点 /api/pricing 的目录折成 magpie 的模型表；sk- 钥匙直接读余额与逐条用量；视频模型走 magpie 的 /v1/videos 三件套 |
| 页面插件 + 本地服务 | magpie 的插件页是 connect-src 'none' 的沙箱，页面自己发不出请求。所以插件起一个只监听 127.0.0.1 的 HTTP 服务，页面导航过去，界面由服务提供 |

 安装

包已发布到 npm：@fish-under-sea/magpie-dragonapi（npm · GitHub）。

两种装法，任选其一：

| 方式 | 怎么做 |
| --- | --- |
| Discover（推荐） | magpie 窗口 → Discover → Unofficial。这个仓库打了 magpie-plugin topic，package.json 里也有已提交的 magpie.page.file，所以会按 magpie.name / magpie.summary 列出卡片，点它安装 |
| 命令行 | magpie plugin add @fish-under-sea/magpie-dragonapi |

npm 拉不到时（内网、镜像抽风）：到 Releases 下
fish-under-sea-magpie-dragonapi-0.3.0.tgz，解包成目录，再 magpie plugin add  ——
plugin add 认 path，和从文件夹加插件是同一条路。

装好后：Settings → Plugins 里出现 DragonAPI 行（带一张页面），供应商列表里出现 DragonAPI。

 只装不配也能看到模型广场——目录走站点公开的 /api/pricing，不需要任何凭据。
 要看余额、读用量、建钥匙，才需要下面的钥匙与 PAT。

 为什么不照抄 NearToken

NearToken 那套「页面里点充值、点连接」依赖两个本站没有的东西：

1. 设备授权（/api/dsh/device/）——那是 neartoken.cc 的私有补丁，DragonAPI 没有。本站登录要过人机校验，PAT 只能在浏览器会话里创建，插件代不了。
2. 请求头切分组（x-neartoken-group）——DragonAPI 不读这个头。它的分组是钥匙的属性：TokenAuth 里 userGroup = tokenGroup，一把钥匙绑死一个分组。

所以这里的做法是：

- 分组 = 账号。一个分组一把钥匙，magpie 里就是多个账号；每个账号的模型清单只列它那一组的模型，宿主自己会把请求送到对的账号（上游 magpie 的 AccountServes 保证）。
- 登录 = 贴钥匙，或用 PAT 让插件替你建钥匙。

 三步接入

 1. 在站点建一把钥匙

到 控制台 → API 密钥 新建，选好分组（分组决定能调哪些模型、按什么倍率计费），复制 sk- 开头的钥匙。

 2. 在 magpie 里添加账号

打开供应商列表里的 DragonAPI，点「添加账号」，两种方式任选：

| 方式 | 做什么 | 适合 |
| --- | --- | --- |
| DragonAPI API Key | 把 sk-… 粘进去 | 最常见；一把钥匙一个分组 |
| 用访问令牌按分组自动建钥匙 | 插件调站点 API 建一把新钥匙并直接绑成账号 | 想少跑一趟控制台 |

第二种要先在插件页面里填访问令牌（PAT），见下一节。它在 magpie 里表现为第二条登录方式，选完分组就自动建好并绑上。

 3. 需要多个分组就重复第 2 步

每个分组加一个账号。magpie 的供应商编辑器里会列出多个账号，每个账号只带它那一组的模型。

 访问令牌（PAT）

建钥匙、看钥匙列表、看账户资料都要 PAT。它只能在浏览器里创建：

1. 登录控制台 → 头像 → 安全 → 访问令牌 → 新建；
2. 勾选权限：
   - profile:read —— 读账户与可用分组（建钥匙必填）
   - api_key:read —— 读钥匙列表
   - api_key:write —— 建钥匙 / 删钥匙
   - api_key:reveal —— 看钥匙完整明文
   - usage:read —— 读用量流水
   - wallet:read —— 读订阅、套餐与邀请（只读展示）
3. 复制 nap- 开头的令牌，粘到插件页面的「访问令牌」页。

 旧版访问令牌已停用（站点返回 ACCESS_TOKEN_LEGACY_RETIRED），必须用新的 nap- 令牌。

PAT 存在本地：/dragonapi-state.json，权限 0600。它必须明文存——每次建钥匙都要用。文件里不存任何 sk- 钥匙明文，那些由 magpie 自己的 plugin-auth.json 保管。

保存 PAT 时插件会并行探四个只读端点（账户资料 / 钥匙列表 / 用量 / 订阅），每次最多等待 12 秒：

| 情况 | 行为 |
| --- | --- |
| 四个端点都说令牌无效（401/403） | 拒收，并说清是权限不够还是令牌失效 |
| 能用一个、缺另一个 | 照样存下，提示缺哪一格、哪些功能会失败（例如只缺 profile:read 时建钥匙会失败，但读用量照常） |
| 站点连不上 / 返回验证页 | 照样存下，标成「未验证」，稍后刷新即可再确认 |
| 写不进状态文件 | 直接报错并给出文件路径——不会出现「提示已保存、重启后消失」 |

 界面里有什么

四个标签页：账户概览 / 模型广场 / 使用日志 / 访问令牌。整页限高——页头、标签、页脚固定不动，
超长内容在面板或卡片里滚动；账户页统一面板滚动，确保订阅、推荐和密钥始终可达。

| 页 | 内容 |
| --- | --- |
| 模型广场 | 左侧筛选（14 个分组带倍率与数量、11 家厂商带品牌图标）+ 右侧搜索、类型分段、分组横幅。一张卡 = 一个模型：站点把同一个模型在多个分组里各卖一份（189 行 / 125 个模型），卡片把它的全部分组都列出来（不省略、不折叠成「+N」），价格给跨分组的区间（如 $0.12–0.32/M）而不是只报最低价。卡内含供应商图标、名称/厂商、说明、计费方式、输入·输出·缓存价、分组、端点。纯展示，没有启用/停用开关——本站做不到 NearToken 那种按分组启停，所以这里不给假开关，也不伪造健康度数据 |
| 模型详情 | 点卡片上的「详情」打开（居中面板）：价签 → 概览 → 计
