botmux


  



  
  
  
  
  
  
  
  
  
  


在飞书里遥控你的 AI 编程 CLI。一条消息启动一个会话，每个会话一个独立 CLI 进程，实时流式回传——手机、电脑、终端三端同步。


  📖 文档 ·
  🚀 快速接入 ·
  ✨ 效果展示 ·
  English



  


---

Daemon 监听飞书消息，为每个新会话自动 spawn 一个独立的会话进程，把 AI 编程 CLI / Agent 的输出实时流式回传成飞书卡片，并提供可交互的 Web 终端。它不重造 Agent 能力，而是直接桥接你已经在用的工具（30+ CLI / Agent 适配器，见 支持的 CLI / Agent）。

 它解决什么

- Agent 收不到通知、手机控不了 — CLI 跑在开发机上，人在手机上。botmux 把每轮输出推成飞书卡片，随时随地查看 / 追问 / 打断，还能开可写 Web 终端直接操作。
- CLI 不感知飞书上下文 — 把机器人拉进话题群 / oncall 群，@ 一句就在你本机的代码库里开跑；会话可以用 /relay 原样搬到另一个群，上下文一点不丢。
- 单个 Agent 不够用 — 同一个群里放多个不同 CLI 的机器人，@ 谁谁干活，让 Claude Code 和 Codex 一起 review 同一个 MR、各自独立分析、观点不同自动互怼。

 5 分钟接入

 一次飞书扫码即可连续建好应用、配全权限并自动发版（手动创建 / 粘贴凭证也是 setup 中的可选路径）。

bash
curl -fsSL https://raw.githubusercontent.com/deepcoldy/botmux/master/install.sh | sh
botmux setup                  一次扫码建应用 → 选 CLI → 选工作目录（自动配权限 + 发版）
botmux start                  启动 daemon（botmux autostart enable 设开机自启）


- 自包含单文件二进制：运行时与 PTY 已内嵌，安装和运行都不依赖本机 Node。支持 Linux / macOS（x64 / arm64，macOS 正式版提供稳定 Apple Developer ID 签名），Windows 用户请在 WSL2 中使用。
- 平滑升级：执行 botmux upgrade 或重跑上述 curl 命令即可原地安全更新。
- 源码安装更新：Dashboard「版本与更新」支持普通更新，以及预览、确认并备份后强制覆盖本地改动；恢复方法见本地源码更新。
- 完整指南：包含 Lark 国际版、手动配置权限与排查，见 5 分钟快速接入文档。


习惯使用 Node / npm 生态？也可以通过 npm 安装（内嵌同一份二进制）

bash
npm install -g botmux         需要 Node = 22 执行安装本身


npm 包内包含相同的自包含二进制，安装后命令与行为完全一致。升级同样建议重跑 curl 命令或 botmux upgrade。



然后私聊机器人、或 botmux dashboard 拉个群即可开始对话。

 核心场景

- 实时流式卡片 — 每轮对话一张实时刷新的卡片，终端画面原样截图回传；一键显示/隐藏输出、翻屏、重启/关闭/接管会话。
- 多机器人协作 — 同群多 bot @mention 路由，不同 CLI 背后不同模型，天然多样性；方案评审 / 代码 review / 技术选型让它们互相挑刺。
- 零注入模式 — 跳过框架注入的 prompt / 角色 / 技能，纯净任务直达 CLI，转写自动回传；适合 lead-bot 派活、sub-bot 专注执行。
- 群内真人独立 lane — 可复用 Dashboard 的「跨身份打断隔离（XPI）」开关，让同一群里的真人各用独立 CLI 上下文和 git worktree；消息仍公开可见，引用别人的任务仍可走建议/确认协作。
- 多话题并行编排 — 给编排者一个大任务，它自动在群里种话题、拉各 bot 起独立会话跑流水线，飞书任务面板一眼看完所有子任务进度。
- 可交互 Web 终端 — 不只是看输出，浏览器 / 手机直接操作 CLI，移动端带悬浮快捷键栏（Esc、Ctrl+C、方向键）。
- 会话接入 & 接力 — tmux / Zellij / Herdr / Orca（实验性）里跑到一半，手机 /adopt 接入；/relay 把整个会话（原进程、原记忆）搬进团队群继续。
- 定时任务 & 外部触发 — 自然语言配周期任务（报警分析 / 群总结）；从外部系统编程式触发用 Webhook 或 API 任务触发。
- Oncall 模式 & 语音总结 — 拉进 oncall 群，任何成员 @ 即在项目目录排查；配好 TTS 后每张卡片页脚会多一个 🔊 语音总结按钮，让模型「说人话」。

更多特性：角色与团队 · 文件沙盒 · 最终回答三态反馈 · Dashboard 管控面 · tmux 会话常驻 · 飞书会议智能体展示。

 中心化平台（开源，可自托管）

单机用 botmux 不需要任何中心服务。机器多了、要在外网打开、或者想和团队一起用时，可以自己部署开源的 Botmux Platform（MIT），用飞书登录，把各台机器上的 botmux 汇总到一个网站：

- 随处打开：每台机器主动向平台建立出站隧道，不用开入站端口；在网页上就能打开任意一台机器的 Dashboard 和 Web 终端，飞书单点登录。
- 机器总览：在线状态、daemon 版本、一键升级，可以给机器加协管者。
- 团队协作：团队与飞书协作群、Issue 看板，还能找到同团队、在别人机器上的机器人拉进群一起干活。
- 个人凭据库：在平台授权一次飞书，平台按需给已绑定的机器发短期凭据，机器人就能以你的身份调用 lark-cli。

接入一台机器：在平台网页点「绑定新机器」，把给出的 botmux bind  拿到这台机器的终端执行。部署方式见 平台仓库，接入与使用见 中心化平台文档，也可以先看 3 分钟讲解视频。

 按 Bot 设置零注入

适合 lead-bot 派活、sub-bot 专注执行的多 Agent 流水线。开启后，botmux 仅传递纯净的任务正文与附件，跳过所有框架级系统提示、逐轮提醒、身份信封、角色描述和技能目录注入，由底层 CLI 转写自动采集回传最终回答。

- ✨ 效果展示与配置指南：飞书文档图文演示
- 📑 技术实现与兼容矩阵：零注入模式规范文档

开启方式：
- Dashboard：「Bot 配置」→ 选中 Bot →「高级」开启「零注入」（或在「Agent 配置」中开启分组统一管理）；
- bots.json：在对应条目中设置 "promptInjection": "none"（设为 "default" 或移除该字段恢复原状）。
