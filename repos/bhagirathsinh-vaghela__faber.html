README

Faber

A coding-agent server and web UI built for long sessions: the prompt cache keeps hitting, work survives restarts, and you can drive it by voice from a desktop or a phone.

Faber is my agent harness, built on top of OpenCode (see NOTICE). I use it daily.

New here? Start with the getting started guide.

 Measured

From my own use over three months: 161,633 Anthropic requests, 2026-07-10 to 2026-10-10. The cache numbers hold month by month; the linked pages have the method and the breakdown.

| Metric                                                                                  | Value                                                                                                               |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Input tokens served from cache                                                          | 99.05%, between 98.8% and 99.3% every month                             |
| Requests that rewrote the conversation cache mid-session                                | 0.08%, never above 0.11% in a month, at a median request of 224k tokens |

 Highlights

Cost

- The prompt prefix stays byte-identical across turns, sessions, repos, plan/build switches, keep-warm pings and compaction. The system prompt is split by how often it changes, and the two stable blocks are cached for an hour. Prompt caching
- Compaction summarizes on the session's own cached prefix instead of rewriting it. Compaction
- Reverting to an earlier message, or editing a prompt, continues on a cache hit. Cache-safe revert
- A per-session daemon re-sends the request just before the conversation's cache entry expires, so a session waiting on you or on a long tool call resumes on a cache hit. Keep-warm
- Cost is computed on the server, with cache writes priced by lifetime. Usage and cost

Reliability

- Every shell command is a durable job. It returns inline if it finishes within 5 seconds; otherwise it reports back when it ends, even if the server restarted in between. Background jobs
- Subagents run in the background, start on the parent's cache, can inherit the parent conversation, and can be limited to a named tool preset. Su
