openkit

 Personal project. This is an opinionated setup shared as-is. There is no
 support or response-time guarantee; issues and PRs are handled on a best-effort
 basis. Fork it and adapt it to your own workflow.

A framework of toggleable, configurable tools and skills for OpenCode V2.

openkit is one plugin you install once. Inside it live independent items
grouped into categories — tools may contribute agent-callable functions,
slash commands, skills, hook injections, and bundled scripts; skills are
self-contained instruction packages you enable on their own. You
turn individual items on or off and tune their settings through configuration,
without touching the plugin itself.

Every category is an instance of one generic engine: a KitCategory descriptor
pairs shipped items with the policy the engine needs (default enabled state,
whether the category carries settings, and one registration hook). Adding a new
category is a descriptor plus a folder — the config, /kit, schema, and
lifecycle layers do not change. See
Categories.

- Framework-first: the conventions for adding items matter more than any one
  item. A new tool is a folder plus a registration; a new skill is a folder plus
  a barrel line.
- On by default: a tool activates unless config or the tool itself says
  otherwise (defaultEnabled: false); bundled skills default to on too.
- Isolated: one item failing to configure never stops the kit or the other
  items from loading.

The package ships two tools: background-subagents
(on by default; forces every subagent call to run in the background so the parent
keeps control while a child works) and
context-injections (on by default;
injects built-in behavioral rules — each individually toggleable — plus your own).
A rule that needs a capability the request does not advertise is skipped for that
request, such as subagent-driven for a leaf subagent with no subagent tool. It is
global and system-level: its rules complement project AGENTS.md/instructions
without overriding higher-priority instructions or explicit approval gates, so
do not duplicate them there.
hello remains as an authoring example, but is not
registered or exposed at runtime.
