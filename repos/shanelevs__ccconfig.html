CCConfig

简体中文 | English








多应用 AI 配置管理工具，同时提供 uTools 插件与独立桌面应用（macOS / Windows）两种形态。

把十五个 AI 编程 CLI 的供应商、模型、MCP、Skill、插件与 Token 用量收进一个界面，一键切换供应商，不必再手改 TOML/YAML/JSON。

 功能特性

- 统一应用切换 — 十五个 AI CLI + 跨 agent 的「通用配置」，各自独立配置，一键切换
- API 配置管理 — 逐应用读取、保存、切换供应商配置，本工具不管理的字段原样保留（未知键往返不丢）
- 供应商/模型主数据 — 共享的供应商与模型库（API Key AES-256-CBC 加密），支持 OpenAI Chat Completions / OpenAI Responses / Anthropic Messages / Google Generative AI 四类协议，一键下发到任意受支持的 agent
- 本地网关 — 把选中的供应商/模型暴露在 http://127.0.0.1:，对本机任意 agent 提供 Anthropic / OpenAI Chat / OpenAI Responses 三种协议，跨协议自动转换（含流式）；「模型映射」模式下用固定映射名（如 pro / plus）对外，每个映射名可配置最多 3 个上游模型，支持只使用第一个 / 报错自动切换 / 随机调用 / 依次调用四种调配策略；换上游只改映射，响应里的 model 也会改写成映射名（默认开，可关），所以各 agent 的使用统计显示的是映射名而不是上游真实模型名
- MCP 管理 — 逐应用 MCP Server 配置 + 实时工具发现画布；通用配置里的共享 MCP 按机器开关镜像写入本地 JSON 文件
- Skill 与插件管理 — 从 SkillHub / 魔搭社区安装 Skill，或粘贴 skills.sh 详情页链接 / npx skills add 命令一键安装到 ~/.agents/skills，并用 skills 同级的 .disabled 停用目录启停；管理 Claude Marketplace 插件、OpenCode plugin 数组、Pi Extension
- 使用统计 — Token 用量、模型分布、GitHub 风格贡献墙热力图；通用统计页另有按天/按周堆叠的 Token 柱状图，可按模型或 Agent 拆分看用量构成
- 订阅用量 — 手动添加已订阅的服务（目前 open-design），用本机浏览器的登录态代查 5 小时／周额度，同时显示在桌面版托盘面板
- 批量编辑 / 导入导出 / 外观 — 按供应商聚合一键改 URL+Key，JSON 文件或压缩加密字符串导入导出；外观支持跟随系统 / 固定浅色 / 固定深色，深色下可选动态背景特效
- 中英双语 — 默认跟随系统语言，可在「设置 → 通用」中切换简体中文 / English

 支持的应用

| 应用 | 配置文件 |
|---|---|
| Claude Code | ~/.claude/settings.json（MCP 在 ~/.claude.json） |
| OpenCode | ~/.config/opencode.json / opencode.jsonc |
| Pi Agent | ~/.pi/agent/settings.json + models.json |
| omp | ~/.omp/agent/models.yml + config.yml（统计读 sessions/ 与 archive/sessions/）|
| Reasonix | ~/.reasonix/config.toml + .env（统计读 stats//.jsonl） |
| Codex | ~/.codex/config.toml + models.json |
| Kimi Code | ~/.kimi-code/config.toml |
| MiniMax Code | ~/.minimax/config.yaml |
| Qoder | ~/.qoder/settings.json / ~/.qoder-cn/settings.json |
| ZCode | ~/.zcode/v2/provider_config.json |
| Hermes | ~/.hermes/config.yaml |
| DSH（DeepSeek Harness） | /profiles//cordis.patch.yml |
| Grok Build（xAI 官方 CLI） | ~/.grok/config.toml |
| Cline | ~/.cline/data/settings/providers.json + models.json（MCP 在 cline_mcp_settings.json） |
| Command Code | ~/.commandcode/providers.json + settings.json（key 在 auth.json，MCP 在 mcp.json，Taste 在 taste/） |

各应用的字段级规则见 docs/architecture.md。

 安装

uTools 插件 — 在 uTools 插件商店搜索 CCConfig 安装。

桌面应用（macOS / Windows） — 从 Releases 下载 .dmg（macOS）或 -setup.exe（Windows）。发布 Release 时 GitHub Actions 会自动构建并挂上这两个安装包；都需要本机已安装 Node.js ≥ 18（应用刻意不内置运行时）。

本地构建（当前平台）：

bash
npm install
npm run tauri:build
 macOS → release/CCConfig__.dmg
 Windows → release/CCConfig__x64-setup.exe
 Tauri 原始产物仍在 src-tauri/target/release/bundle/ 下，
 scripts/collect-release.mjs 在构建末尾复制一份到仓库根的 release/


应用数据存放于 ~/.ccconfig/（Windows 为 %USERPROFILE%\.ccconfig）。关闭窗口只是隐藏到托盘，本地网关继续运行：左键单击托盘图标打开状态面板（网关统计、订阅用量、快捷动作），右键单击显示窗口。

如果 Node 是通过 nvm/fnm/volta 安装的、从 Finder / 开始菜单启动后应用找不到它，可显式指定：

bash
 macOS
CCCONFIG_NODE=$(which node) open -a CCConfig
 Windows（PowerShell，先设置变量再启动应用）
$env:CCCONFIG_NODE = (Get-Command node).So
